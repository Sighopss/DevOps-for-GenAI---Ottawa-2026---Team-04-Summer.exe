## 1. Purpose and scope

**Intended use.** An on-call ML or SRE engineer reconstructs **one** AI request after the fact — its spans, RAG hops, tool call, token counts, cost, and errors — without the observability system itself becoming the data leak.

**Users.** Two demo tenants, `tenant-a` and `tenant-b`, as Cognito users. These are judge accounts, not real customers. TraceVault is not carrying anyone's production traffic during this hackathon.

**Non-goals.** Fleet KPI dashboards. Grafana. Autonomous remediation. Root-cause analysis generated by a model. Custom domain. Multi-region. This is a flight recorder for a single request, not an operations console.

**Prohibited uses.** Storing raw prompts or raw PII. Reading another tenant's flights. Committing credentials. Attaching real end-customer traffic without a fresh data-protection review, which is out of scope for 48 hours. Using the audit trail to monitor individual employees.

## 2. Risk classification

**Overall: high** — and specifically because of one property, not many.

The material risk is **prompt persistence**. An observability tool sits directly in the path of the most sensitive text in an AI system: the prompt. Anything that records prompts inherits the sensitivity of every prompt it has ever seen, and a store that holds them becomes a higher-value target than the application it observes. Last year's comparable project persisted prompts in plaintext (see the Lineage section of [`README.md`](README.md)), which is what makes this the risk worth designing around rather than a hypothetical.

| Risk | Impact if realised | Control | Residual |
|---|---|---|---|
| Raw prompt or PII persisted | High — regulated data at rest in a system with no data-protection review | Fail-closed redaction at ingest; only `prompt_hash` + masked preview stored | Low by design, **but** dependent on deny-list coverage; Presidio is optional and absent in CI |
| Cross-tenant read | High — one tenant reads another's prompts | `custom:tenant_id` compared in `vault-read`, 403 not 404 | **Mitigated** — implemented in `vault/read/tenant_guard.py`, tested (`vault/tests/read/test_isolation.py`), and demonstrated against the live deployment 2026-08-22: tenant-b → tenant-a trace returned `403 "tenant mismatch"` with no spans (`docs/RED_TEAM.md` B1) |
| Ingest key compromise | Medium — attacker appends spans for one tenant; cannot read | Key ≠ user JWT; per-tenant scope; rotation in Secrets Manager | Low; no read capability from a write key |
| Prompt injection | Low — no privileged action exists to steer toward | Schema-only ingest, text stored inert; one read-only tool | Low |
| Cost runaway | Low — demo-sized throttle and timeouts | API throttle, Lambda timeout, `maxTokens` 256 | Low, untested (issue #52) |

Both of the top two controls are now built, tested, and demonstrated in operation (redaction fail-closed and cross-tenant 403 — `docs/RED_TEAM.md`). The remaining honest gaps are infrastructure, not vault behaviour: the edge TLS floor is TLSv1 (default CloudFront certificate, #101), and WAF — now attached to CloudFront and blocking (#100) — cannot front the HTTP API, so ingest flood bounds still rest on the in-Lambda caps plus API Gateway throttling.

## 3. Data governance

| | |
|---|---|
| **Sources** | The demo prompt typed into `demo-app`; the RAG corpus in `demo-app/corpus/` (3 synthetic markdown files written by us); Bedrock model output; span metadata generated by `sdk/tracevault`. |
| **Sensitivity** | Demo data is **synthetic PII only** — a fake email and a fake SSN, injected deliberately by `scripts/demo_pii_flight.sh --pii` to prove redaction works. No real personal data enters this system. |
| **Classification** | Prompt text: sensitive, **never persisted**. `prompt_hash` (sha256): pseudonymous, persisted. `prompt_preview`: masked, ≤200 chars, persisted. Token counts, cost, timings, span graph: operational metadata, persisted. `tenant_id`: tenant identifier, persisted and used as the isolation key. |
| **Retention** | DynamoDB TTL on `expires_at`, **7 days** (`VAULT_TTL_DAYS`). Lambda CloudWatch log groups, **7 days**. S3 payloads have no lifecycle rule yet — a known gap, since the Dynamo summary expires before the S3 object does. |
| **Permitted use** | Reconstructing the flight the data belongs to, for the tenant that owns it. Nothing else. Not model training. Not analytics across tenants. |
| **Minimisation** | The prompt is reduced to a hash plus a masked preview at the earliest point the vault controls. Unknown span fields are rejected rather than stored, so the schema is the ceiling on what can be retained. |
| **Encryption** | S3 and DynamoDB under a customer-managed KMS key with rotation. HTTPS only in transit. |

**Known gap:** S3 payload objects outlive the DynamoDB summary because no bucket lifecycle rule is configured. The flight becomes unreachable at 7 days (the index is gone) but the object persists. Masked-only content, so not a PII exposure, but it contradicts a plain reading of "7 day retention" and should either be fixed with a lifecycle rule or stated in the demo. Owner: Trevor.

## 4. Human oversight

**Humans view traces. No agent changes infrastructure.** That is the whole oversight posture, and it is enforced structurally rather than by policy:

- The agent in this product has **exactly one tool**, `get_doc_metadata`, and it is read-only over three local markdown files. There is no write tool, no delete tool, no shell tool, and no network tool in the tree. There is therefore no "high-impact action requiring confirmation", because no high-impact action is reachable.
- No model output is executed, and no model decides anything operational. Bedrock produces an answer string that is displayed and recorded. It cannot trigger a deployment, modify a policy, or write to the vault.
- Infrastructure changes require a human-approved `terraform apply`. CI can apply on `main`, but `main` is protected and only Trevor merges.
- AI-assisted code was used to build this product (disclosed in [`AI_USAGE.md`](AI_USAGE.md)); every line reached `main` through a pull request that a human reviewed and a human merged. No agent has merge rights.

**Who approves what**

| Change | Approver |
|---|---|
| Any code merge to `main` | Trevor |
| `contracts/` (HTTP surface, span schema) | Trevor + Alexis + Michael, all three on the PR |
| `terraform apply` | Trevor, explicitly, per apply |
| Production deploy | Trevor, via GitHub Environment `prod` reviewer |
| A tenant's data | The tenant, scoped by `custom:tenant_id`; no cross-tenant override exists, including for admins — the `admin` Cognito group does not bypass the tenant check |

## 5. Transparency

What a user is told, in the product rather than in this file:

- **`REDACTED` badges** wherever a prompt would otherwise appear, so masking is visible rather than silent.
- **Model name, token counts, and `cost_usd`** on the `llm` span — the user sees which model answered and what it cost.
- **TTL** surfaced on the flight, so the user knows the record expires in 7 days.
- **A one-line limitation on the welcome page**: prompts are stored masked, retention is 7 days.
- **Tenant badge**, so which tenant's data is on screen is never ambiguous.

Stated limitations of the system itself: TraceVault records what the SDK is wired to record — an unwrapped call is invisible to it. The masked preview is lossy on purpose and cannot be reversed. `prompt_hash` allows recognising an identical prompt, not recovering it. Redaction is deny-list-driven and Presidio is optional, so a novel PII format could pass masking, which is why the residual-PII check and fail-closed behaviour exist as a second line.

Owner for the UI surface of this: Michael (`web/`, issues #59, #62). **Not built yet** — `web/` does not exist, so today these are requirements, not delivered behaviour.

## 7. Monitoring

| Indicator | Signal | Status |
|---|---|---|
| **Operational** — is it up | `GET /health` → `200 {"ok":true}`, served without a Lambda | Configured; never yet curled against a live endpoint |
| **Operational** — is it erroring | CloudWatch alarm, API 5xx ≥ 5 in 5 minutes | Configured in `infra/cloudwatch.tf`; never fired or tested |
| **Behavioural** — what did the AI do | The flights themselves. This product *is* the telemetry: span graph, RAG hops, tool call, tokens, cost, errors | Emitted by `sdk/`, stored by `vault-ingest`, readable through `vault-read` (`GET /v1/traces*`, tenant-scoped, audited). The Explorer renders it; its live-data wiring is Michael's remaining piece |
| **Safety** — is redaction holding | `redaction_failed` count. A non-zero rate means unmaskable content is arriving | Behaviour implemented and tested; no metric or alarm on the counter yet |
| **Abuse** — is someone probing | `401`/`403` rates; WAF sampled requests | WAF configured; no alarm on auth failures yet |
| **Cost** | `cost_usd` per span, aggregated per flight | Field carried end to end; **the live Bedrock path currently hardcodes `cost_usd = 0.0`**, so real cost is not computed — gap, owner Trevor |
| **Logs** | Lambda log groups, 7-day retention, no raw prompts | Retention configured; the no-prompts property is tested |

**Scale question — what breaks first at 10x.** The bottleneck is `vault-ingest` concurrency and the Bedrock quota, in that order. The response is to raise the API throttle and Lambda reserved concurrency in `infra/envs/*.tfvars` and request a Bedrock quota increase. DynamoDB and S3 are on-demand and absorb it. The answer is deliberately not "add Kubernetes". Untested — issue #52.

## 8. Change management

| Artifact | How it changes |
|---|---|
| **Code** | Feature branch → PR → committed handoff in `handoffs/` with Handbook evidence → review → **Trevor merges**. `main` is protected; no direct push, no force-push. |
| **The HTTP contract and span schema** | `contracts/` requires Trevor, Alexis, and Michael on the PR. Frozen at hour 0 deliberately so lanes could build in parallel against a fixed wire format. Amendments are recorded in the handoff, not applied silently. |
| **Prompts** | The demo prompt is a CLI argument, not stored server-side. The system prompt is one line in `demo-app/src/demo_app/bedrock.py` and changes only by PR. |
| **Models** | Add or change an id in `infra/envs/*.tfvars`, which also updates the IAM allowlist, since the policy is generated from that list. A model cannot be swapped in at runtime without an infrastructure change — deliberate. |
| **Tools** | Adding an agent tool requires a code change to `demo-app/src/demo_app/rag.py` and a PR. The one-tool allowlist is a reviewed property, not a runtime configuration. |
| **Policies and infrastructure** | Terraform only. No console edits — a console change would be overwritten by the next apply and would not appear in review. |
| **Required checks** | `gitleaks` and `trivy-fs` on every PR (no path filter). `sdk`, `vault`, `web`, `infra` jobs are path-filtered. |

## 9. Incident response

Every row names a person. Escalation terminates at Trevor; there is no pager, which is a disclosed 48-hour non-goal rather than an oversight.

| Scenario | Immediate behaviour | Response | Owner |
|---|---|---|---|
| **Redaction cannot complete** | Ingest returns `400 redaction_failed` and **stores nothing**. The flight is lost; no partial or unmasked record is written. | Investigate the input class that failed, extend the deny-list, add a regression test. Data loss is the accepted outcome. | Alexis |
| **Raw PII found at rest** | — | Treat as a breach of the core guarantee. Identify the ingest path that bypassed masking, delete affected objects, add the case to `vault/tests/redact/`, and disclose it rather than quietly patching. | Alexis, escalate to Trevor |
| **Cross-tenant read observed** | Should be `403`. | Revoke the affected Cognito session, fix the claim comparison in `vault-read`, add the case to the isolation tests. **Note:** the control is implemented, tested, and verified live returning `403` (`docs/RED_TEAM.md` B1), so an observed cross-tenant read means a regression — treat it as a P1 and re-run `docs/redteam/redteam.sh`. | Alexis, escalate to Trevor |
| **Ingest key compromised** | Key is per-tenant and write-only — no read capability. | Rotate the value in Secrets Manager. No redeploy required; the handler reads the secret at invoke. Old key stops authenticating immediately. | Trevor |
| **Site or API down** | `/health` fails; 5xx alarm fires. | Re-run the last green `deploy.yml`. That is the rollback — one mechanism, no separate script. | Trevor |
| **Bad deploy** | — | Same: re-run the last green `deploy.yml`. `main`-only deploys mean the last green run is always a known-good state. | Trevor |
| **Model unavailable or refusing** | The demo surfaces the error; the flight still records the `llm` span with `status: error`. Observability degrades gracefully rather than failing the request. | Switch to the second permitted model id (`amazon.nova-lite-v1:0`) via `BEDROCK_MODEL_ID`. | Trevor |
| **Ingest endpoint unreachable from the recorder** | SDK does not crash or block. Writes `sdk/.last-flight.json` locally with the same masked spans. | Restore the endpoint; the local file is a fallback for continuity, not a data store. | Trevor |
| **Secret committed to git** | `gitleaks` fails the PR before merge. | If it reached `main`: rotate first, then purge history. Rotation before cleanup, always. | Trevor |
| **Model output is wrong or unsafe** | No automated action is taken on model output — nothing downstream consumes it. | A human reviews the flight. Because the answer drives no action, an incorrect answer is a quality issue, not a safety incident. | Trevor |

## Current state, stated plainly

This card describes the system as designed and, where noted, as built. Being specific about the difference is itself a governance control:

- **Built, tested, and demonstrated live:** redaction (fail-closed, 115 vault tests), ingest with tenant-scoped writes, the read path, tenant-isolation 403, the audit trail, span emission, the one-tool agent, the CI security gates — the vault half verified against the deployed stack on 2026-08-22 (`docs/RED_TEAM.md`).
- **Built and applied, but not regression-tested:** the cloud controls in Terraform. The stack was applied 2026-08-22; no automated assertion re-checks encryption, IAM scope, or the public-access block as it changes.
- **Known not in force:** the TLS 1.2 floor at the edge (default CloudFront certificate, #101). WAF is attached to CloudFront and blocking as of 2026-08-22 (#100), but it cannot front the HTTP API, so ingest is not WAF-protected.
- **Deployed:** the API and the Explorer are live. The Explorer's live-data path still needs the API base URL baked into the web build; the fixture view works.

Anything in this document phrased as running behaviour that falls into the last three categories is a requirement, not a claim. [`README.md`](README.md) **Demo integrity (P-15)** holds the authoritative built-versus-deployed table.
